How it works

From running session to exact request.

A metadata-only directory hands off to OMP's own encrypted client. The terminal stays the source of truth; the phone gets one private page.

  1. 01 · Discover

    Every live session, automatically.

    Each collaboration-enabled omp process appears within one 10-second discovery poll. No per-session command, QR code, or copied link.

  2. 02 · Triage

    The oldest ask rises first.

    When sessions wait for input, Needs you promotes the oldest request with bounded metadata. The prompt itself stays in OMP.

  3. 03 · Control

    Open the exact live request.

    Open request fetches the link when you tap and hands it to OMP's encrypted client once. Replaced or exited sessions fail closed instead of opening something newer.

What runs where

The gateway finds sessions. OMP keeps the secrets.

Stock OMP >= 18.1.20 ships the collaboration controller and a private local registry. The gateway only reads that registry and brokers the handoff; it never carries transcripts.

  1. omp × N your terminals

    Publishes each interactive session to OMP's private registry when collab.autoStart is view or control.

  2. omp-gatewayd 127.0.0.1 only

    Reads the registry, polls each session every 10 seconds, and keeps a memory-only metadata directory.

  3. Tailscale Serve tailnet HTTPS

    Exposes the directory to an exact login allowlist over your tailnet. Funnel is never enabled.

  4. OMP Sessions your phone

    Shows metadata only. Tapping View or Control fetches the link from OMP at that moment and never stores it.

  5. OMP relay end-to-end encrypted

    OMP's pinned collab-web client connects through OMP's own relay. The gateway is out of the path.

Private by design

Fail closed by default.

View can read sensitive work and Control can steer it, so both links are treated as bearer capabilities. Every release runs distinctive-synthetic-secret leak scans across logs, storage, caches, URLs, and CI artifacts before it is qualified.

  • Loopback-only daemon

    omp-gatewayd binds to 127.0.0.1 (and optionally ::1), never to a public interface.

  • Exact login allowlist

    Requests arrive only through TUN-mode Tailscale Serve from a Tailscale login on your allowlist. A userspace-networking client makes every peer look local, so the daemon answers 403 instead of trusting the header.

  • Per-tap, memory-only capabilities

    View and Control links are fetched from OMP only when you tap, handed to the client once, and never stored, logged, or cached — not even in the memory-only registry.

  • Metadata-only directory and alerts

    Session lists, live events, and push notifications carry bounded session metadata only, never collaboration links or prompts.

  • No transcripts, telemetry, or third-party assets

    OMP's embedded client connects through OMP's encrypted relay. The gateway stores no transcripts and loads no external scripts, fonts, or analytics.

  • Stale sessions cannot be opened

    Every launch checks that the session is still the one you tapped; replaced or exited sessions fail closed instead of opening something newer.

One-time setup

Three steps, then plain omp.

Setup is one-time: afterwards every new session appears on its own within 10 seconds. Nothing here needs a custom OMP build or a gateway-specific OMP plugin.

  1. Enable collaboration once in OMP

    # must report at least 18.1.20
omp --version
# or view for read-only sharing
omp config set collab.autoStart control

    Start participating sessions with plain omp after changing this setting; already-running processes do not pick it up.

  2. Install the gateway

    tar -xf omp-session-gateway-*-bun.tar
cd omp-session-gateway-*-bun
bun apps/gateway/src/cli.js install \
  --origin https://host.tailnet.ts.net \
  --allow you@example.com
bun apps/gateway/src/cli.js serve-guidance

    Download and verify the published archive first. Run the Tailscale Serve command that serve-guidance prints, grant your login HTTPS access to the host in your tailnet policy (example), then confirm with bun apps/gateway/src/cli.js doctor. Windows uses the PowerShell steps.

  3. Open OMP Sessions on your phone

    Open your configured HTTPS address from an allowlisted Tailscale device and add OMP Sessions to your Home Screen. Operations covers service management and updates; troubleshooting by symptom covers common issues.

A narrow job

Use something else when you want more than a directory.

The gateway is a directory and launch broker for running terminal sessions, not a replacement chat client or a public dashboard. The comparison cites dated primary sources for each alternative.

  • A browser-hosted OMP workspace with persistent sessions, kanban, and an inboxomp-deck embeds the OMP SDK in-process.
  • Agent web chat or a remote terminal across several CLI agentsoh-my-portal provides skills, RPC, and terminal access over Portal tunnels.
  • A browser workspace for other coding CLIsCloudCLI (claudecodeui) targets Claude Code, Cursor CLI, and Codex; pi-agent-dashboard targets pi, not OMP.
